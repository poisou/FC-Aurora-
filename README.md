# DataSimulator

一个用于导入和查看可变长度 BIN 数据包的 Qt Widgets 桌面工具。

## 页面结构

- `MainWindow`：顶层窗口，只负责承载页面栈。
- `wid_stack`：固定外壳 + 内容页面栈。顶部产品栏和设备管理、协议规则、数据源管理、场景并行、数据回看五个切页始终显示；点击“数据源管理”或“数据回看”切换内容区，不隐藏切页导航。
- `wid_review`：独立的数据浏览页面类，实际作为 `QWidget` 嵌入 `wid_stack` 显示，不会创建独立弹窗；包含文件导入、总线类型选择、数据分页、进制切换、数据编辑和保存功能。
- `wid_datasource`：独立的数据源管理页面，包含数据源分组、上传/自定义/删除按钮、统计卡片、数据源列表、分页状态、进制切换和 HEX 预览表格。
- `wid_customdatasource`：独立的自定义数据源编辑页面，包含数据源名称和总线类型选择。`FC`、`Aurora` 和 `以太网` 统一显示发送时间、步进、帧个数和帧列表。帧列表每页显示 50 行，支持上一页、下一页和指定页跳转，每行提供编辑和删除操作。帧编辑对话框保存后，帧列表的“帧长”显示实际数据字节总数，“值”显示完整数据内容，并统一使用两位大写十六进制格式。点击“保存”时，程序使用 6 字节 `AHEAD` 占位结构体，按“AHEAD + 帧数据”逐行组合；每行 AHEAD 最后两个字节写入该行帧长包含的 1024 字节包数。文件写入 `<可执行文件目录>/MYDATA/<数据源名称>.bin`，再按总线类型写入对应 SQLite 表并刷新数据源列表。点击数据源管理页的“自定义数据”切换到该页面，点击“返回”回到数据源管理页。
- `AuroraFrameEditDialog`：帧列表点击“编辑”后弹出的数据帧信息窗口，Aurora 参数设置仅包含 `PW`、`PRI`、`TOA`，每包长度固定为 1024 字节，长度右侧提供包数设置。数据值表格每页固定显示 1024 字节（16 列 × 64 行），支持上一页、下一页和指定页跳转。点击“生成”时总数据量为 `包数 × 1024` 字节；每个包从独立的 1024 字节偏移开始，勾选字段在对应字节位置按“初始值 + 包索引 × 步进”生成。三个字段使用可配置的“起始字节 + 字节数量”范围，并从当前页的 1024 字节中按大端组合后以十进制显示；直接修改 `PW/PRI/TOA` 时会写回当前页的对应字节范围。16/10 进制下拉框只影响数据值表格，不影响三个参数。勾选“随机数”时全部数据字节随机填充，未勾选时全部填 0。保存后参数回写到对应帧。
- `DataSourceUploadDialog`：上传数据源配置对话框，可选择文件路径、FC/Aurora/以太网总线类型和数据源名称；完成后将记录加入数据源列表。
- `AuroraFileImporter`：独立实现 Aurora 的 `6 + n × 1024` 流式解析。
- `TcpFileImporter`：独立实现 TCP 的 `6 + n` 流式解析，并校验 `n ≤ 1024`。
- `FcFileImporter`：独立实现 FC 的 `6 + n` 流式解析，当前规则与 TCP 相同，但代码与 TCP 分离。
- `BinFileImporterBase`：仅提供取消状态和导入进度/完成/失败信号，不包含具体协议解析逻辑。

### 界面类与 UI 文件对应

| 界面类 | 对应界面文件 | 用途 |
| --- | --- | --- |
| `MainWindow` | 无独立 `.ui`，中央加载 `wid_stack.ui` | 顶层窗口标题、图标、尺寸 |
| `wid_stack` | `wid_stack.ui` | 顶部导航、设备管理和内容页面切换 |
| `WidReview` | `wid_review.ui` | 数据回看、包分页、数据段编辑 |
| `wid_datasource` | `wid_datasource.ui` | 数据源列表、数据库、MYDATA 文件和数据段预览 |
| `wid_customdatasource` | `wid_customdatasource.ui` | 自定义帧生成、分页、AHEAD 文件保存 |
| `DataSourceUploadDialog` | `datasourceuploaddialog.ui` | 上传文件路径、总线类型、名称配置 |
| `AuroraFrameEditDialog` | `auroraframeeditdialog.ui` | Aurora 参数、1024 字节分页和序列生成 |

设备管理页左侧列表包含 `FC设备`、`Aurora设备`、`以太网设备`。点击设备后，右侧设备名称和类型同步更新，其中以太网设备类型为 `以太网`。数据源管理使用独立页面，不会进入 `wid_review`；只有“数据回看”入口显示 `wid_review`。程序启动后以普通窗口模式显示。

数据源上传完成后会加入管理列表。“创建时间”读取文件的文件系统创建时间；“时间范围”显示数据浏览列表中所有上传文件创建时间的最小值和最大值，不包含自定义记录。“值”列显示文件内容的前 16 字节 HEX，上传文件记录的该列可直接编辑，支持空格分隔或连续的十六进制输入；修改后点击“保存修改”会原位写回对应 BIN 文件的前 16 字节，不改变文件长度。上传类型为 `FC` 或 `以太网` 时，“数据长度”显示文件的实际总字节数；上传类型为 `Aurora` 时，程序会在后台按照 `6 字节包头 + n × 1024 字节数据段` 的格式逐包解析，并在完成后将“数据长度”更新为所有包的 `n × 1024` 累计值，不包含每包 6 字节包头。解析期间该列显示“解析中…”，格式不正确时显示“解析失败”。数据源列表每页显示 10 条记录，可通过“上一页”、“下一页”或输入指定页码跳转。点击任意数据源行会整行高亮，下方按与数据回看相同的格式显示：第一列为 8 位偏移，后续为 `00–0F` 共 16 个字节列，最多加载前 64 KB 内容，并支持 16/10 进制切换；下方数据段表格每页显示 50 行，同样支持上一页、下一页和指定页跳转，切换数据源时会自动回到第一页。选中行后点击“删除”会移除该数据源，同时清空下方数据段列表，不会自动选中其它行。

上传文件点击“完成”后，程序会先把文件异步复制到 `<可执行文件目录>/MYDATA`，再写入 SQLite 数据库。数据库固定位于 `<可执行文件目录>/qsqlite/WT_FCData.db`，目录和数据库不存在时会自动创建。`FC`、`Aurora`、`以太网` 分别写入 `table_data_FCsource`、`table_data_Aurorasource`、`table_data_TCPsource`，每张表只包含 `name`、`date`、`filePath` 三个字段，其中 `filePath` 保存 `MYDATA` 中复制文件的绝对路径。程序启动时会从三张表恢复数据源列表；在界面中删除已上传记录时，会同步删除对应的数据库行和 `MYDATA` 中的物理文件。文件删除只允许发生在 `MYDATA` 目录内部，数据库删除和文件删除使用同一事务流程，任一步失败都会保留列表记录。MYDATA 中同名文件会自动追加 `_1`、`_2` 等序号，避免覆盖已有数据。

## 文件格式

- 文件扩展名：`.bin`
- 包头长度：6 字节
- `n`：取包头第 5、6 字节，字节序由 `BIN_HEADER_BIG_ENDIAN` 宏配置
- Aurora 单包结构：6 字节包头 + `n × 1024` 字节数据段
- TCP 单包结构：6 字节包头 + `n` 字节数据段，要求 `n ≤ 1024`
- 数据包数量：从文件开头连续解析到文件末尾

### 字节序配置

包头 `n` 的读取字节序由统一宏控制，Aurora 和 TCP 共用同一配置：

```cpp
#ifndef BIN_HEADER_BIG_ENDIAN
#define BIN_HEADER_BIG_ENDIAN 1
#endif
```

- `BIN_HEADER_BIG_ENDIAN = 1`：使用大端序，默认值。
- `BIN_HEADER_BIG_ENDIAN = 0`：使用小端序。

两字节解码统一由 `BinFormat::decodeDataCount()` 完成。桌面测试文件 `tcpdemo.bin` 使用大端序生成，包头末两字节为 `03 FA`，对应 `n = 1018`。

## 导入流程

1. 选择或拖入 `.bin` 文件，界面会显示文件名、完整路径和文件大小，但此时不会读取文件数据。
2. 在“总线类型”中选择 `FC`、`Aurora` 或 `以太网`。
3. 选择 `Aurora` 时按 `n × 1024` 字节的数据段解析。
4. 选择 `以太网` 时，内部使用 `TcpFileImporter` 按 `n` 字节的数据段解析，并校验 `n ≤ 1024`。
5. 选择 `FC` 时使用独立的 `FcFileImporter`，当前按与以太网相同的 `6 + n` 规则解析和显示。

数据浏览列表会根据总线类型切换列结构：未选择总线类型时列名为空；选择 `Aurora` 时显示包序号、文件偏移、6 字节包头、数据块 n、数据长度、数据预览 6 列；选择 `FC` 或 `以太网` 时显示包序号、文件偏移、数据长度、数据预览 4 列。

导入文件后会逐包读取包头，并根据最后两个字节得到 `n`。Aurora 读取 `n × 1024` 字节数据段，TCP 和 FC 暂时读取 `n` 字节数据段。若包头不足 6 字节、TCP/FC 的 `n > 1024`，或文件剩余长度小于该包声明长度，程序会给出格式错误提示。列表每页显示最多 10 包；可以通过上一页、下一页或输入指定页码跳转，选择任意一行可查看 HEX / ASCII 数据段。

大文件采用后台流式解析：工作线程只读取包头并跳转到下一包，不把整个文件载入内存。数据段只在查看详情或生成当前页预览时按需读取，HEX 详情单次最多显示 64 KB。导入期间界面会显示进度，并支持取消操作。

数据段以 16 列字节表格显示，可直接双击单元格修改。表格工具栏可在 `16进制` 和 `10进制` 之间切换：16 进制输入范围是 `00-FF`，10 进制输入范围是 `0-255`。切换只改变显示方式，不改变底层字节。修改过的单元格会高亮，点击“保存到文件”后，当前数据段的修改会原位写回 BIN 文件，其它数据包不受影响。对于超过 64 KB 的数据段，表格只加载并保存前 64 KB。

数据浏览表格的每一列值在 `populateCurrentPage()` 中都有对应代码注释，说明包序号、文件偏移、包头、数据块数量、数据长度和预览值的含义。`WidReview` 内部可以直接调用以下函数为当前页表格的指定行列赋值：

```cpp
bool success = setDataValue(value, row, column);
```

其中 `row` 为当前页表格行索引（从 0 开始），`column` 为数据浏览表列索引（0-5）。该函数只修改表格显示值，不直接修改 BIN 文件。

也可以在启动时直接传入文件路径：

```powershell
DataSimulator.exe D:\data\sample.bin
```

## 构建

项目同时支持 CMake 和 qmake，要求 Qt 5.15 或 Qt 6，并启用 Widgets 模块。

使用 CMake：

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.x.x/msvc2019_64"
cmake --build build --config Release
```

也可以直接使用 Qt Creator 打开 `CMakeLists.txt` 或 `DataSimulator.pro`。
